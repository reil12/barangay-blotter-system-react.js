# Barangay Blotter System (React.js + Flask)

A web application for barangay residents to file and track blotter (incident) reports, and for barangay admins to manage those records, send mediation meeting notices, view analytics, and manage users and announcements.

The frontend is built with **React.js** (Vite). The backend is a **Flask** JSON API that stores data in **Microsoft SQL Server**.

## Features

**Residents**
- Sign up with email verification (6-digit code, valid for 10 minutes)
- Log in with email and password, then enter a 6-digit code sent by email
- File a blotter report with an automatically generated case number (`BRG-YYYY-NNNN`)
- View own reports with search and status filter
- Read announcements, emergency contacts, and the "How to File" guide with barangay ordinances

**Admin**
- View all blotter records with search and status filter
- Edit records, change status (Pending, Settled, Dismissed), and delete records
- Print a blotter certificate
- Send a mediation meeting notice (date, time, place, instructions) to the complainant by email
- Analytics dashboard (monthly totals, incident types, weekly comparison)
- Export all records to Excel
- Search users, delete non-admin users, and post or delete announcements

## Requirements

- Python 3.10 or newer
- Node.js 18 or newer (with npm)
- Microsoft SQL Server (Express is enough) and SQL Server Management Studio (SSMS)
- ODBC Driver 17 for SQL Server
- A Gmail account with an App Password, for sending email

## Setup

### 1. Create the database

1. Open SSMS and connect to your SQL Server instance.
2. Open `database_backup.sql` and run it. It creates `BarangayBlotterDB` with the `Users`, `Incidents`, and `Announcements` tables.
3. Update the server name in `app.py` (`get_db()`) to match your instance, for example `SERVER=YOUR-PC\SQLEXPRESS`.

### 2. Install the Python packages

```bash
pip install flask flask-mail pyodbc openpyxl
```

### 3. Configure the email and secret key

The email account and secret key are read from environment variables. Set them before you start the app:

| Variable | Value |
|---|---|
| `MAIL_USERNAME` | Your Gmail address |
| `MAIL_PASSWORD` | Your Gmail **App Password** (not your normal password) |
| `SECRET_KEY` | Any long random text |

On Windows (Command Prompt), for example:

```bat
set MAIL_USERNAME=you@gmail.com
set MAIL_PASSWORD=your-app-password
set SECRET_KEY=change-this-to-a-long-random-text
```

### 4. Build the React frontend

The built files are already in `static/react/`. Rebuild them only if you change the frontend code:

```bash
cd frontend
npm install
npm run build
```

### 5. Run the app

Run the Flask server from the project folder (the one that contains `app.py`):

```bash
python app.py
```

Open **http://127.0.0.1:5000** in your browser.

## Development mode

To edit the React code with live reload, use two terminals:

```bash
# Terminal 1: backend (from the project folder)
python app.py

# Terminal 2: frontend (from the frontend folder)
npm run dev
```

Open **http://localhost:5173**. Requests to `/api` are forwarded to Flask on port 5000.

## Main API routes

| Method | Route | Who | Purpose |
|---|---|---|---|
| GET | `/api/me` | Anyone | Current logged-in user |
| POST | `/api/login` | Guest | Check email and password, send login code |
| POST | `/api/verify-login` | Guest | Check the login code |
| POST | `/api/signup` | Guest | Create an account and send verification code |
| POST | `/api/verify-signup` | Guest | Verify email |
| POST | `/api/logout` | Anyone | Log out |
| GET | `/api/my-reports` | Resident | Own reports |
| POST | `/api/incidents` | Resident | Submit a report |
| GET | `/api/announcements` | Resident | Announcements |
| GET | `/api/admin/incidents` | Admin | All records |
| GET/PUT/DELETE | `/api/admin/incidents/<id>` | Admin | View, edit, or delete a record |
| POST | `/api/admin/incidents/<id>/status` | Admin | Change status |
| GET | `/api/admin/incidents/<id>/certificate` | Admin | Certificate data |
| POST | `/api/admin/incidents/<id>/meeting-notice` | Admin | Email a meeting notice to the complainant |
| GET | `/api/admin/analytics` | Admin | Chart data |
| GET | `/api/admin/export` | Admin | Excel download |
| GET | `/api/admin/users` | Admin | User list |
| DELETE | `/api/admin/users/<id>` | Admin | Delete a non-admin user |
| POST/DELETE | `/api/admin/announcements[/<id>]` | Admin | Post or delete announcements |

## Notes and limitations

- Reported persons are entered as free text. They are not linked to user accounts and do not receive emails.
- Meeting notices are sent only to the complainant and are not stored in the database.
- The printable certificate has placeholders for the barangay name and officials (`[YOUR BARANGAY NAME]`, `HON. [KAPITAN NAME]`). Replace them in `frontend/src/pages/CertificatePage.jsx` before official use.
- Case numbers are based on the number of records in the current year. They may repeat if records are deleted.
- The app is meant to run on a local machine or local network. It does not include HTTPS.

## Troubleshooting

- **"can't open file 'app.py'"**: You are in the wrong folder. Open a terminal inside the folder that contains `app.py`.
- **"React build missing"**: Run `npm run build` inside the `frontend` folder.
- **Cannot connect to the database**: Check the server name in `get_db()` and make sure SQL Server is running and `BarangayBlotterDB` exists.
- **Email not sent**: Check `MAIL_USERNAME` and `MAIL_PASSWORD`. Gmail requires an App Password with 2-Step Verification turned on.
- **`Cannot find package 'vite'`**: Run `npm install` inside the `frontend` folder before `npm run build`.
